# ルーレット効果・カテゴリコンボ設計

## 用語

ここでいう「コンボ効果」は連続HITではない。同じカテゴリのアーティファクトをバッグに集め、カテゴリごとの所定数に達したときに発生するゲーム既存の効果を指す。

## バニラのカテゴリ設計

ゲーム内カテゴリの効果は、そのカテゴリが扱う属性・戦闘要素を伸ばす。日本語攻略Wikiのカテゴリ解説では、たとえば次のように説明されている:

| カテゴリ | バニラでの専門性/効果の方向 |
|---|---|
| 交渉 (`Savvy`) | 経験値・リーフ経済。コンボで交渉力とリーフドロップが伸び、所持リーフに応じたダメージ効果も得る |
| 堅固 (`Sturdy`) | 物理ダメージ・武器攻撃 |
| 精密 (`Precision`) | クリティカル率・クリティカルダメージ |
| 風の歌 (`WindSong`) | 攻撃速度、武器ダメージ、ダッシュ |
| 元素 (`Elemental`) | 最も高い属性ダメージを伸ばし、全元素ダメージを増幅 |

確認できた閾値の例:

| カテゴリ | 閾値と効果 |
|---|---|
| 交渉 | 2個: 交渉力+10、リーフドロップ+15%。4個: 交渉力+15、所持リーフ200ごとに敵へのダメージ+1%（最大20%、「黄金の手」） |
| 風の歌 | 2個: 攻撃速度+8%、4個:+12%、6個:+16%、8個:+12%、10個: 武器ダメージ+15%とダッシュ回数+1 |
| 元素 | 2個: 最も高い属性ダメージ+5、4個:+6、6個:全元素ダメージ+10% |

バニラでは同カテゴリのアーティファクトを集め、カテゴリごとの必要数に達すると段階的なコンボ効果が発生する。コミュニティWikiの一覧は19カテゴリ・74段階を掲載している。各段階の効果は確認できる一方、段階をまたいだ効果が累積するのか、上位段階が下位段階を置き換えるのかは同Wikiでも未確認とされているため、ここでは断定しない。

## MODのルーレットカテゴリとバニラ参照

- ルーレット本体と「高速ルーレット」は、MOD独自カテゴリ `Gambling` に属する。
- カテゴリは `Savvy` を複製して登録するが、`setStatus` を空にし、`comboEffectPrefab` は専用の `RouletteGamblingComboEffect` に差し替える。交渉カテゴリ由来の経済コンボは適用しない。
- `ComboEffectBase` の既定説明 `ComboEffect_Xxx` はギャンブルカテゴリ専用のローカライズ済み説明に置き換える。未設定のままだとカテゴリ効果欄に既定キーがそのまま表示される。
- ギャンブルカテゴリの所持数に応じて、ルーレットの報酬・バフを強化する。2個で+20%、4個で+40%、6個以上で+60%。段階は累積せず、最も高い段階の倍率を適用する。
- 強化対象は小当たり・ジャックポットのゴールド、中当たり・ジャックポットの一時ダメージバフ量と時間、大当たりの回復・範囲ダメージ、ジャックポットの無敵時間。抽選確率、スピンコスト、熱狂・連勝・フィーバー、無料スピン連鎖は対象外。
- 小・中・大・ジャックポットの当たり回数はカテゴリコンボ効果欄に表示する。ハズレはカウントしない。
- 当たり判定、報酬、コンボ用の当たり回数記録、所有者クライアントのリール演出はサーバー側の同じ抽選結果に基づく。無料スピンの連鎖もサーバーが順番と上限を管理する。
- 熱狂ゲージ・連勝・フィーバーはルーレット効果の短期進行で、カテゴリ個数による報酬強化とは別に管理する。進行状況はルーレットUIとギャンブル2個コンボ欄に表示する。詳細は [ルーレット「熱狂・連勝・連鎖」効果](./roulette-fever-chain-design.md) を参照。
- 死亡、またはルーレットをすべて失った場合に、当たり回数カウントをリセットする。高速ルーレットだけを失った場合はリセットしない。
- 大当たり範囲ダメージは引き続き `PhysicalDamage` を参照する。中・ジャックポットの一時ダメージバフは `AllDamageBonus` で適用し、カテゴリ段階の報酬強化倍率を反映する。

## ゲームコードで確認できた仕組み

インストール済みゲームの `Assembly-CSharp.dll` から確認:

- `ItemCategoryEntity` は `setStatus`（必要数 `itemCount` と適用ステータス `status`）と `comboEffectPrefab` を持つ。
- `GridInventory` はアーティファクト所持数をカテゴリ別に集計する。カテゴリに `comboEffectPrefab` がある場合、`ComboEffectBase` を生成し、集計数を `Enable(count)` に渡す。
- `ComboEffectBase.addStatByCombo` は閾値ごとのステータス効果を定義する。`Charm_Basic.AdvancedComboRequirement` はカテゴリIDと必要数を指定し、`GetSetEffectCount(category)` で条件を判定する。
- `COMBO_BONUS_DAMAGE` は有効なカテゴリコンボ効果数に応じた最終ダメージ補正に使われる。連続HITカウンターではない。

## 実機での確認項目

- カテゴリコンボ画面で2個・4個・6個の段階と結果別カウントが表示されること。
- 2/4/6個の段階で報酬・バフ効果とバフ時間がそれぞれ+20/+40/+60%になり、段階が重複適用されないこと。
- ゴールド、回復、範囲ダメージ、一時ダメージバフの量・時間、無敵時間に強化が適用されること。
- 抽選確率・コスト・熱狂/フィーバー・無料スピン連鎖がコンボで変わらないこと。
- 死亡またはルーレット全喪失時に当たり回数カウントと短期進行がリセットされること。
- 高速ルーレットだけを失った場合に当たり回数カウントと短期進行が維持されること。
