# バニラUI踏襲の振り返り（コンボ説明の熱狂・連勝分割）

## 何が起きたか
「熱狂と連勝で説明を分けて」「バニラと同じ表示に」という依頼に対し、正解（バニラの `<tag=...>` 詳細キーワード）に到達するまで、複数回やり直しが発生した。

## 迷走した経路と原因
| 試した案 | ユーザー指摘 | 原因 |
|---|---|---|
| 説明文に改行を入れる | バニラと表示形式が違う | バニラの表示を確認せず、見た目だけ文字で似せた |
| `UI_CommonTooltip` を複製して別枠 | バニラと違うものを使うな | バニラのコンボ説明が使う部品（`UI_SynergyTooltip`）を調べず、別の部品を流用した |
| コンボ一覧に「ルーレット:熱狂」等の別行を追加 | ギャンブルのコンボUIとは別物 | 「個別表示」を「別UI／別項目」と解釈した。実際は同じツールチップ内の詳細カード |
| 独立ツールチップ（Harmonyパッチ） | 同上 | 同上 |
| 正解: `<tag=KeywordId>` + `KeywordEntity.displayDetails = true` | - | `UI_SynergyTooltip.OpenKeywordsCoroutine` を読んで判明 |

### 根本原因
1. **バニラで同じ表示を出している実例のコードを最初に読まなかった。** 太陽剣などの説明から「コンボ説明内で詳細カードが出る」仕組みを逆引きすべきだった。
2. **ユーザーの示した具体例（太陽剣など）を実装根拠にせず、自分の想像で部品を選んだ。**
3. **動作確認の環境を取り違えた。** スクリーンショット時点ではSteam Workshop版DLLが有効だったが、ローカル更新版が動いていると前提し、「MODが無効」と断定して誤りだった（アイテムが付与されている時点でMODは有効）。
4. 実機確認前に「できた」と判断しやすかった。

## 再発防止チェックリスト
- バニラUIに合わせる依頼では、**実装前にバニラの該当クラス（今回は `UI_SynergyTooltip`、`KeywordDatabase`）を逆引きし、同じ経路を使う**。別部品を複製しない。
- ユーザーが例を挙げたら、その例のデータ（どの文字列にどのタグが入っているか）から調べる。
- 「別々に表示」と言われたら、どの粒度（行・カード・枠）かを、バニラの実例に当てて判断する。バニラに無い別UIを作らない。
- 表示確認では、**どのDLLが読まれているか**（Workshop版かローカル版か）をログと更新日時・ハッシュで先に確かめる。MODの有効/無効はアイテム付与の有無で判断できる。
- 実機で確認するまで「直った」と断定しない。

## 技術メモ
- 詳細カードは、コンボ効果の `effectName` 文字列内の `<tag=KeywordId>` をTMPリンクとして `UI_SynergyTooltip` が解決して作る。カテゴリの `defaultEffect` では動かない。
- キーワードIDにコロンを含めない（タグ解析がコロンで分割するため）。
- 登録は `HorayModAPI.OnLoadKeywordDatabase` のコールバック内で行う。
- 閾値2の報酬文と熱狂・連勝タグは、**同じ `ComboEffectElement` に改行区切りで入れる**。別要素にすると別行扱いになる。
- C# 9では非逐語的な補間文字列内で改行できないため、先に変数へ組み立てる。
- 設計の詳細は [roulette-combo-design.md](./roulette-combo-design.md) を参照。
